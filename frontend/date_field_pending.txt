# Owner ask 2026-10-29: *"for payroll hours approval the calendor should open up instead of enetring
# it manuallu"*. A bare `<input type="date">` opens its calendar only from the small glyph at the
# field's right-hand edge; a click anywhere else lands a caret in mm/dd/yyyy and the date gets typed.
# `src/components/DateField.tsx` is the one home that fixes that, and `prove_date_field.mjs` is the
# ratchet.
#
# WHY A RATCHET AND NOT A HARD RULE. There were 168 date inputs across 89 files when this shipped.
# Converting every one in a single change would put a blind diff across half the product, and that is
# not a decision a lock should make on the owner's behalf. So the rule is the one that stops the
# bleeding: the two SHARED shells are converted (StandardFilterBar and ReportShell), which is what
# gives every range-filtered report the calendar — Hours Approval among them — plus the payroll and
# workforce family the ask came from. Everything still listed below behaves as it did yesterday.
#
# THE RULE: a NEW bare date input fails the build. This file may only get SHORTER.
#   · converting a file -> DELETE its line here (the guard fails on a stale entry too)
#   · a new date field  -> use <DateField>, and add NOTHING here
#
# Each line is a bare path relative to frontend/, and nothing else. The guard checks PRESENCE, so a
# file holding three date inputs leaves this list only when all three are converted.
