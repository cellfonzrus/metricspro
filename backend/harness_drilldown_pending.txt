# Owner, verbatim: "update in index thta drilldown is needed for every report geenerated from any
# data which comming from within the platforma as a defalut".
#
# EVERY report route the platform serves appears here EXACTLY ONCE, with its state. The guard
# `harness_drilldown_coverage.py` fails the build when a route in the report directory is missing
# from this file, when a route here no longer exists, or when the `owes` count GROWS. So a new
# report cannot ship without either a drill-down or a written-down reason -- which is the owner's
# "by default", enforced rather than remembered.
#
# STATES
#   shared     - renders the one shared drill-down (components/DrillDownPanel.tsx over
#                core/report_drilldown.py). This is what a new report does.
#   own        - had a drill-down of its own before §CORE-17 and it names its sources. EXCUSED and
#                NAMED, to converge onto the shared panel; converging one is a PR of its own, and
#                until then the note says what it already does.
#   flat       - shows the source rows already; there is no summarised figure to drill from.
#   not_report - a config screen, a wizard or a work queue. Not a report, so the rule does not apply.
#   owes       - a summarised figure with no way to the rows behind it. THIS COUNT MAY ONLY SHRINK.
#
# Format: <route><TAB><state><TAB><note>. Lines starting with # are comments.
# Audited 2026-10-24; the per-route findings are in the project folder under drilldown-audit/.
